# NesGame 项目开发规范

本文件是仓库级开发、排查和审查规范。开始工作前先阅读；完成改动后按影响范围检查。代码和测试是实际行为的最终依据，规范不能替代对当前实现的确认

## 项目定位

NesGame 是使用 Go 提供服务、浏览器运行 JSNES 的 NES 游戏平台。浏览器通过 HTTP 加载原生 HTML、CSS 和 ES Module，通过 WebSocket 处理大厅、房间、WebRTC 信令、输入和必要的对局状态同步

当前联机模式由客户端运行模拟器：房主维护唯一逻辑时间轴并推进主要对局，P2 使用房主帧号驱动模拟器；P2 发送输入并接收房主的压缩状态校准。P2P 优先，打洞失败时使用服务器 Relay。服务端负责连接、昵称、房间、消息转发和协议边界，不要把当前实现描述成服务端权威模拟

## 目录职责

- `main.go`：读取 `config.json`，检查目录，启动 HTTP 服务和 Hub，处理优雅关闭
- `api/`：静态资源、游戏列表、ROM、封面、在线数据和 WebSocket 路由
- `game/`：Hub、房间、客户端连接、WebSocket 生命周期、信令和 Relay 协议
- `frontend/`：当前使用的原生 HTML、CSS、JavaScript 和第三方浏览器资源
- `frontend/js/`：页面路由、设置、大厅、输入、JSNES 驱动、音频和联机会话
- `frontend/lib/`：浏览器端第三方库，除非用户明确要求，不修改或替换其中内容
- `roms/`：本地 NES ROM 和可选的同名说明、封面文件
- `dist/`：发布目录，由 `build.ps1` 生成，不直接编辑
- `build.ps1`：Windows 发布构建脚本

## 配置与路径

- 服务配置只从根目录 `config.json` 读取，当前字段包括 `host`、`port`、`frontend`、`roms` 和 `basePath`
- `basePath` 为空表示根路径；非空时必须是以 `/` 开头且不带结尾斜杠的子路径
- 新增前端接口、资源或 WebSocket 地址时，使用 `frontend/js/common.js` 的 `assetPath()`，不得写死根路径
- 前端资源、API 和 WebSocket 在根路径与子路径下都必须可用

## 构建与生成文件

- 用户自行决定何时打包；未经用户明确要求，不运行 `build.ps1`，不修改或覆盖 `dist/`
- `build.ps1` 会执行 Go 检查、复制 `frontend/` 和 `roms/`、生成版本文件、压缩文本资源并编译服务端
- 需要构建时使用 PowerShell 7，并确认输出只写入根目录 `dist/`
- 临时测试文件和临时构建目录只放在根目录 `build/`，不要混入源码目录
- 未经用户明确要求，不提交 Git、不创建提交、不代替用户打包

## 通用修改原则

- 修改前先读取目标文件及其相关调用方，特别是用户或格式化工具已经改动的文件
- 保留工作区已有改动，不擅自还原、删除或覆盖无关内容
- 优先沿用现有目录、模块、命名和依赖，不为未来需求预先增加抽象或依赖
- 不通过终端命令改写源码文件；源码修改使用编辑工具
- 函数或方法即使只有一条语句，也使用常规多行函数体
- 只记录实际行为、必要约束和维护原因，不添加与实现不符的说明
- 修改已有文件时，只补充改动涉及的必要注释，不进行无关的大规模格式化

## 注释规范

- Go、JavaScript、PowerShell 和 Shell 中的每个函数或方法，上一行放简短的中文用途注释；JavaScript、PowerShell 和 Shell 不要求注释以函数名开头
- Go 文件的 `package` 声明前放简短中文包注释
- Go 函数注释遵循 GoDoc，首句以函数名开头；JavaScript 使用自然中文说明用途或原因
- JavaScript 注释直接描述用途或原因，不以函数名开头，例如使用“返回指定格上的炸弹”，不要使用“bombAt 返回指定格上的炸弹”
- 配置字段、协议字段、并发状态、重要常量和不直观的变量需要中文注释
- `const (...)` 块内的常量说明写在声明行尾；独立常量在声明前一行说明
- 注释必须与当前实现一致，不为显而易见的语法增加无意义注释
- 所有注释末尾不加句号等标点；CSS 注释保留 `/* */`，JavaScript 单行注释使用 `//`
- HTML 默认不添加解释实现方式的注释；只有结构用途不明显或维护确实需要时才添加

## Go 服务端与 WebSocket

- `game/Hub` 的主循环串行处理房间和连接命令；WebSocket 收发 goroutine 通过 `commands` 通道与 Hub 通信
- `Client` 的读写由独立 goroutine 负责；不要从多个 goroutine 直接写同一个 WebSocket
- 房间成员、昵称、消息来源和房间操作必须由服务端校验，不能信任浏览器传来的身份或状态
- 当前服务端不运行 NES 游戏规则；不要把客户端的画面、位置、碰撞或存档数据当作服务端已验证的权威结果
- 新增或修改 WebSocket 消息时，同时更新 `game/wire.go`、对应的前端发送与解析逻辑，以及相关 Go 测试
- 联机开局先通过 `state` 发送一次压缩运行时状态，P2 载入后发送 `state_ack`；只有状态确认后才开始持续帧同步，状态请求只用于重新对齐
- 房主本地读取存档后必须重新发送 `state`（`force=true`）把新进度推给 P2；jsnes 存档不含帧号，房主需在存档记录中保存并恢复 `frameCount`，P2 收到新 `state` 后按其中的帧号重置自己的推进起点
- 联机 P2 不本地读档，其模拟器由房主帧驱动，本地读档会被房主 `state` 覆盖；P2 的存档读取应禁用或提示等待房主同步
- 持续帧同步使用专用 `q` 消息，格式为 `{"t":"q","d":"q..."}`；`d` 是 8 字节数据的无填充 Base64URL 表示，包含 16 位环形帧号、连续两帧的 P1/P2 输入掩码和连发相位
- 房主每完成两帧发送一个 `q` 包，即使双方没有输入也必须持续发送；P2 按房主帧号推进，丢帧时从最早可用帧恢复，不能永久等待缺失帧
- P2P 直接发送 `q...` 字符串，Relay 使用专用 `q/d` 外层；旧版 `f2`、10 字节紧凑帧和 `relay/payload` 只保留接收兼容，不得作为新发送格式
- 输入消息应尽量只在按键状态变化时发送；完整模拟器状态必须压缩并限频，远端输入不能触发回声发送
- P2P 和 Relay 必须保持相同的消息语义；Relay 不能阻塞 Hub，慢客户端不能拖住房间处理
- WebSocket 队列满、连接断开或房主离开时，必须按现有生命周期策略清理成员并通知对端
- 服务端清洗昵称、房间相关外部文本和聊天内容；前端显示外部文本使用 `textContent` 或等价安全 API

## 前端、模拟器与音频

- 前端使用原生 ES Module，不引入 Vue、Vite、Node 运行时或新的构建依赖，除非用户明确要求
- 复用 `frontend/js/common.js` 的 DOM 工具；不得把外部输入拼接到 `innerHTML`
- 布局优先使用 Flex，只有 Flex 无法表达时才使用 CSS Grid
- 画布只负责显示模拟器画面；联机状态、输入和存档同步逻辑不能依赖画布渲染结果
- 音频在浏览器本地通过 Web Audio API 和 AudioWorklet 处理，不通过 WebSocket 或 Relay 传输
- 修改输入、模拟器或联机同步时，注意键盘、触屏和手柄输入需要合并，远端输入不能触发回声发送
- `NesRunner` 的 P2 模式使用 `externalClock`，只能由房主帧消息调用 `advanceFrame`；P2 不运行自己的本地时钟，也不显示本地 FPS
- 虚拟手柄必须在 `pointerdown` 时立即按下；使用触点到按键的映射和按键计数支持多指同时按键、单指斜向以及方向区拖动切换，释放一个触点不能误释放其他触点仍持有的按键
- 加入房间的游玩标题优先使用大厅房间的游戏展示名，不得直接显示 ROM ID；游玩页状态栏在窄屏下必须允许换行，不能裁掉 P2、网络状态或 FPS 信息
- 窄屏普通模式的虚拟手柄位于画面下方；移动端横屏全屏模式覆盖在画面两侧，画布和手柄都必须受视口与安全区约束，不能造成横向或纵向溢出
- 静态 HTML 和无扩展名入口使用 `Cache-Control: no-store`；未版本化静态资源最多缓存一天
- 修改浏览器交互时，通过浏览器开发工具验证关键 DOM、画布尺寸、网络消息和控制台错误；涉及联机同步时确认无输入期间仍有 `q` 帧、P2 能持续推进，且正常流量中不再发送旧的嵌套 `relay/payload/f2` 包

## 安全与资源约束

- ROM、封面和其他文件接口必须复用现有 ID 校验，禁止让请求路径直接穿透到任意文件
- 不在日志、测试输出或注释中写入密码、令牌和其他敏感信息
- 传输协议优先使用紧凑字段；修改消息大小、频率或压缩策略时，同时检查断线、重连和旧客户端兼容性
- 不直接复制其他作品的原曲、素材或大段代码；音频和视觉资源使用原创或项目已有资源

## 测试与交付检查

未涉及构建时，按影响范围执行以下检查：

```powershell
go test ./...
go vet ./...

Get-ChildItem frontend/js -Filter *.js | ForEach-Object { node --check $_.FullName }
git diff --check
```

涉及 WebSocket、路径或浏览器交互时，使用临时配置和独立端口启动服务，通过浏览器验证登录、大厅、建房、加入、开局、P2P/Relay 和控制台错误。测试结束后停止服务并确认端口已释放

新增 Go 测试放在被测包的 `api/`、`game/` 或根目录中，优先覆盖公开行为、路径兼容、协议编解码和回归问题。除非用户明确要求，不运行发布构建，不修改生成目录，不提交 Git
